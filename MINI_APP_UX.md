# Telegram Mini App: UX и проверка

Mini App работает в существующем `/telegram`. Главная навигация закреплена снизу: Сводка, Гости, Трансфер, Музыка, Банкет. Учтены Telegram safe area и отступ под навигацией. Публичное приглашение, авторизация, worker, RSVP и миграции не менялись.

## Экраны

- Сводка открывается первой: шесть KPI (ответы, придут, не придут, трансфер, музыка, питание), станции, последние музыкальные пожелания, переходы к спискам.
- Гости: компактные карточки с именем, статусом, двумя строками описания и применимыми метками. Полный ответ открывается отдельно.
- Трансфер: списки Купчино и Павловска, копирование имён для водителя, открытие деталей. Старые ответы `needed` без станции вынесены в отдельную группу, самостоятельно приезжающие исключены.
- Музыка: только непустые пожелания участников, оригинальные переносы строк, поиск по имени, копирование всех пожеланий без разбора текста на треки.
- Банкет: количество гостей по каждому выбранному напитку, отдельные свои варианты с именами, список особенностей питания.
- Детали: Основное, Трансфер, Напитки, Питание, Музыка. Пустые необязательные разделы скрыты, удаление с прежним подтверждением находится внизу.

## API и данные

Единственный endpoint остаётся `/api/telegram/mini-app`. Любое действие сначала проходит прежнюю server-side проверку подписи initData, срока auth_date и whitelist. Неавторизованный HTML не содержит RSVP или dashboard.

Добавлен `GET ?action=analytics`: списки трансфера, музыки и питания, агрегаты напитков и свои варианты. Используются только существующие PostgreSQL поля. Guest projection не содержит session ID, cookie или initData.

В обычный ответ списка добавлены `stats.music` и `stats.diet`, а также структурированные имя/описание/трансфер/музыка/питание для карточек. Старые `fields` и статусы сохранены для совместимости.

Поиск `search` ищет подстроку имени без учёта регистра, `%` и `_` не являются wildcard. `sort`: newest, oldest, az, za. Порядок имени использует lower(name) и детерминированную PostgreSQL C collation; `id` разрешает совпадения. Pagination остаётся по 20 записей.

Дополнительные параметры: `transfer=any/self/kupchino/pavlovsk`, `music=any/yes/no`, `diet=any/yes/no`, `alcohol` и `soft` с существующими ID напитков. Сохраняются attendance filter и старые station filters. Параметры проверяются по фиксированным наборам, значения поиска и фильтров передаются через параметры SQL.

Bottom sheet позволяет применить несколько условий одновременно, затем снять их отдельными chips. Поиск имеет debounce 250 ms, устаревший ответ не перезаписывает более новый. Сортировка находится рядом со списком. После удаления повторно запрашиваются список, все KPI и аналитика. Refresh доступен кнопкой возле заголовка.

Агрегаты отражают число участников, выбравших вариант, а не объём напитков. `none` учитывается как действительный вариант. Legacy `wine` показан как «цвет не указан». Пустые/whitespace music и diet не учитываются; данные NOT_GOING в этих разделах не показываются.

## Проверки и screenshots

Unit/integration tests: аналитика, станции, пустая музыка, питание, drinks/custom drinks, все sorts, literal search, combined filters, удаление с обновлением статистики. Существующая security suite проверяет также новое analytics action для всех невалидных способов авторизации.

Browser suite: пять экранов и bottom sheet, copy, filters/search, длинные имена и 300 символов без пробелов, 320/375/390/430 px без horizontal overflow, удаление и empty states. Используются только изолированная in-memory PostgreSQL и синтетический Telegram SDK. Дополнительные QA fixtures существуют только в localhost browser harness, production endpoints не добавлены.

Screenshots находятся в `tests/browser/__screenshots__/chrome/win32/telegram-*.png`. `telegram-review-*` показывают обычных вымышленных гостей; остальные проверяют предельные длины. Публичные эталоны не обновлялись.

Команды:

```text
npm run typecheck
npm run lint
npm test
npm run build
npm run test:browser
npm run check:secrets
```

Проверка выполнена в Chrome с синтетическими Telegram safe-area values. Реальный Telegram WebView на физическом телефоне и production Amvera в этом pass не запускались. Push не выполнялся.


## Банкетное меню: migration 009

Добавлена безопасная migration `009_banquet_menu.sql`. Новые nullable text columns: `hot_appetizer_choice`, `main_course_choice`. Checks ограничивают стабильные ключи; старые строки остаются NULL. Ни данные, ни migrations 001–008 не изменяются. Применяется существующим runtime migration runner при следующем старте приложения; production БД в локальной проверке не использовалась.

Единый файл `src/content/menu.mjs`: `hotAppetizerOptions` (hot_meat/hot_fish), `mainCourseOptions` (main_meat/main_fish). Label/shortLabel можно менять на реальные названия без migration. RSVP, client/server validation, guest detail, filters и analytics используют эту конфигурацию.

Новые GOING требуют оба одиночных значения, помимо прежних обязательных полей. NOT_GOING не отправляет food choices; сервер хранит NULL. Блюда расположены вместе с особенностями питания. При добавлении следующего гостя очищаются оба выбора.

`action=analytics` расширен `food.hotAppetizer` и `food.mainCourse`: id, label, count, guests (id/name). Каждый drink aggregate также содержит guests. Повторное значение в массиве не увеличивает счётчик одного гостя дважды; количество означает гостей, не бутылки/литры. Старые гости без меню видны в отдельной строке «Пока не выбрано».

В «Банкет» четыре группы: горячая закуска, основное блюдо, напитки, особенности питания. Нажатие на блюдо/напиток открывает конкретные имена. Из списка можно открыть детали или скопировать текст «Название — N гостей» и имена. После удаления drill-down выводится из обновлённой аналитики, устаревшие списки не сохраняются. Custom choices подписаны именем и «Свой вариант: ...».

В деталях добавлена секция «Еда»: оба блюда и особенности, если указаны. На сводке компактный блок «Банкет» с четырьмя counts и CTA. Advanced filters дополнены hotAppetizer/mainCourse (any либо допустимые canonical keys); постоянная навигация не расширена.

Новые browser states: rsvp-food-block, telegram-food-drill, telegram-drink-drill, telegram-banquet-320; обновлены RSVP, Banquet overview, сводка, filters, Guest Detail и полные homepage screenshots (из-за увеличения RSVP). Скриншоты первых сцен и остальных публичных секций не обновлялись.
